# Roadmap v0.2

Este roadmap descreve possibilidades futuras. Nada aqui deve ser lido como
capacidade existente na v0.1.

| Item | Prioridade | Motivo | Criterio de aceite |
| --- | --- | --- | --- |
| `SafeLoad` minimo | P1 | Reduz risco de juniors copiarem load direto para producao. | Classe ou helper pequeno com staging, bloqueio de chave nula/duplicada e testes de rerun. |
| `LoadStrategy` simples | P1 | Tira decisoes repetitivas do ponto de maior risco. | Estrategia explicita para append/overwrite/staging sem esconder custo ou semantica do destino. |
| Certificacao lendo destino | P1 | Certificar `DataFrame` em memoria nao prova persistencia. | Certificacao falha quando o dado do `run_id` nao aparece no destino real ou simulado. |
| Idempotencia basica | P1 | Reprocessamento deve produzir estado final previsivel. | Reexecutar o mesmo escopo nao duplica dados. |
| Protecao contra carga parcial | P1 | Falha no meio da escrita nao pode parecer sucesso. | Testes simulam falha antes e depois do commit. |
| Quarantine persistente | P2 | Invalidos precisam de destino auditavel quando nao bloqueados. | Registros invalidos sao persistidos com `run_id` ou a pipeline falha explicitamente. |
| Logs JSON opcionais | P2 | Facilita ingestao por coletores externos. | Eventos podem ser serializados e testados com `json.loads`. |
| Campos operacionais extras | P2 | Ajuda suporte em clusters. | Eventos aceitam `environment`, `job_id` e Spark application id sem quebrar compatibilidade. |
| Matriz CI ampliada | P3 | Reduz divergencia entre suporte declarado e testado. | CI roda nos runtimes oficialmente suportados pela equipe. |

## Fora Do Roadmap Imediato

A v0.2 tambem nao deve transformar o projeto em plataforma generica de dados.

Continuam fora do objetivo:

- orquestracao externa;
- catalogo;
- motor completo de regras;
- UI;
- dependencia pesada de data quality;
- abstracao que esconda `SparkSession`, `DataFrame` ou custo Spark.
